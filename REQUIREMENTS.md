## Общая концепция

При первом запуске контейнера автоматически создаётся один системный интерфейс — **Admin Instance**. Все остальные интерфейсы создаются пользователем вручную через UI. Admin Instance и пользовательские интерфейсы разделены — в UI они отображаются в разных секциях и не смешиваются.

---

## 1. Admin Instance (управляющий план)

Системный AWG2 интерфейс для доступа к веб-панели управления. Администратор сначала подключается к этому VPN, затем открывает UI. В перспективе доступ к веб-UI будет ограничен только подсетью этого интерфейса (на этапе разработки — открыт).

### Параметры (env vars в run.sh / docker-compose.yml)

| Переменная | Назначение | Пример |
|------------|-----------|--------|
| `WG_ADMIN_ADDRESS` | IP адрес интерфейса | `10.0.0.1/24` |
| `WG_HOST` | Публичный IP/домен сервера | `1.2.3.4` |
| `WG_PORT` | UDP порт | `51820` |
| `WG_DEFAULT_DNS` | DNS для клиентских конфигов | `1.1.1.1,8.8.8.8` |
| `JC` | AWG junk packet count | `6` |
| `JMIN` | AWG min junk size | `10` |
| `JMAX` | AWG max junk size | `50` |
| `S1..S4` | AWG size параметры | `64, 67, 17, 4` |
| `H1..H4` | AWG hash диапазоны | `221138202-537563446` |
| `I1..I5` | AWG imitation параметры | `<r 2> <b 0x...>` |
| `ITIME` | AWG timing | `0` |
| `PORT` | Порт веб-UI | `51821` |
| `PASSWORD_HASH` | bcrypt хэш пароля UI | `$2y$...` |

### Поведение при запуске
- Ключи генерируются автоматически при первом запуске, сохраняются в data
- При повторном запуске ключи берутся из файла — не перегенерируются
- Интерфейс поднимается автоматически

### Управление через UI
- Только добавление и удаление пиров
- Параметры самого интерфейса через UI не меняются (только env vars + рестарт контейнера)
- Нет кнопок Start/Stop/Edit для интерфейса

## 2. Data Plane Instances (пользовательские туннели)

Создаются пользователем вручную. Каждый Instance — отдельный WireGuard/AWG интерфейс.

### Начальное состояние
При старте контейнера — нет ни одного data plane Instance.

### Форма создания

| Параметр | Обяз. | Примечание |
|----------|-------|------------|
| Name | ✅ | Произвольное имя |
| IP адрес | ✅ | Адрес интерфейса, напр. `10.10.0.1/24` |
| Listen port | ✅ | UDP порт |
| Protocol | ✅ | `AmneziaWireGuard 2.0` или `WireGuard 1.0` |
| Private key | ✅ | Кнопка Generate (автозаполнение) или ручной ввод. **После создания не редактируется и не отображается в открытом виде.** |
| Public key | ✅ | Автозаполняется при Generate, или ручной ввод |
| Disable Routes | ☐ | Checkbox. Если отмечен → `Table = off` в конфиге. Для S2S/PBR сценариев. |
| AWG параметры | если AWG2 | Jc, Jmin, Jmax, S1-S4, H1-H4, I1-I5. Подставляются из дефолтного шаблона, можно выбрать другой через dropdown "Load from template" |

### AWG параметры в форме
- При выборе протокола AWG2 появляется блок AWG параметров
- Автоматически заполняется из шаблона помеченного как `default`
- Dropdown "Load from template" — перезаполнить из выбранного шаблона
- После выбора шаблона параметры можно редактировать вручную
- H1-H4 рандомизируются заново при каждом применении шаблона
- При выборе Vanilla WG — AWG параметры скрываются

### Инструмент запуска
- AWG2 → `awg-quick` (интерфейс типа `amneziawg`)
- Vanilla WG → `wg-quick` (интерфейс типа `wireguard`)

### Редактирование Instance
- Доступно для любых параметров **кроме приватного ключа**
- После сохранения интерфейс **не перезапускается автоматически** — пользователь делает Stop→Start вручную

### Disable Routes (Table = off)
Checkbox в форме создания/редактирования.
- Не отмечен (дефолт) → `Table` не пишется в конфиг (wg-quick использует `auto`)
- Отмечен → в конфиг добавляется `Table = off`

Назначение: для S2S соединений где маршрутизация управляется вручную (PBR). WireGuard по-прежнему использует AllowedIPs для крипторутинга, но в системную таблицу маршрутов ничего не добавляет.

## 3. AWG2 Templates (Settings → AWG2 Templates)

Именованные наборы AWG2 параметров для быстрого заполнения форм.

### Структура шаблона

| Поле | Тип | Примечание |
|------|-----|------------|
| Name | string | Имя шаблона |
| Default | boolean | Один шаблон помечен как дефолтный |
| Jc | number | |
| Jmin | number | |
| Jmax | number | |
| S1, S2, S3, S4 | number | |
| H1, H2, H3, H4 | string | Зоны/диапазоны. При применении к Instance рандомизируются заново. |
| I1..I5 | string | Свободный текст. Поддержка `<r 2> <b 0x...>` для полной обфускации AWG2. |

### Использование
- При создании AWG2 Instance — автоподстановка из дефолтного шаблона
- Dropdown "Load from template" в форме — перезаполнить параметры из выбранного шаблона
- Параметры **копируются** в Instance в момент применения — изменение шаблона не влияет на существующие Instance

### AWG2 полная обфускация (I1)
По данным сообщества (письменной документации нет): полная обфускация включается когда параметр `I1` начинается с тега `<r 2>`, за которым следует `<b 0x...>` (бинарный blob, имитирующий DNS или другой протокол).

Пример значения I1:
```
<r 2> <b 0x084481800001000300000000077469636b65747306776964676574096b696e6f706f69736b0272750000010001...>
```

## 5. Технические детали (важно для реализации)

### iptables и NAT
- Ubuntu 22.04 использует nftables как дефолтный бэкенд
- Docker устанавливает FORWARD policy DROP через nftables
- PostUp **обязан** использовать `iptables-nft` (не `iptables`)
- PostUp должен добавлять FORWARD ACCEPT в дополнение к MASQUERADE:

```
PostUp = iptables-nft -I FORWARD -i <iface> -j ACCEPT; iptables-nft -I FORWARD -o <iface> -j ACCEPT; iptables-nft -t nat -A POSTROUTING -s <subnet> -j MASQUERADE
PostDown = iptables-nft -D FORWARD -i <iface> -j ACCEPT; iptables-nft -D FORWARD -o <iface> -j ACCEPT; iptables-nft -t nat -D POSTROUTING -s <subnet> -j MASQUERADE
```

### --network host и "already exists"
С `--network host` WireGuard интерфейсы живут в ядре хоста и переживают `docker stop/start`. При повторном `awg-quick up` падает с "already exists" → PostUp не выполняется → нет NAT. Решение: при старте интерфейса всегда регенерировать конфиг, при "already exists" делать down→up цикл.

### Адрес клиента в конфиге
Address в клиентском конфиге (`[Interface] Address`) вычисляется из AllowedIPs пира + маски интерфейса. Не хранится отдельно, не запрашивается у пользователя.

### Приватный ключ
Нигде не отображается в открытом виде. Не редактируется после создания Instance.
